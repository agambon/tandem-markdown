# Changelog

All notable changes to Tandem Markdown are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## 0.1.0 (2026-11-24)

First version.

### Added

- Three views of one markdown file: Source (VS Code's text editor), Rich view (read-only) and Rich editor, with switching that keeps the cursor, the scroll position and the undo history.
- The rich views hold the file's exact text and draw over it, so only what is edited changes in the file.
- Changes made to an open file by another program are merged into the document, including over unsaved typing. When both changed the same words, the user's words are kept unless the user chooses otherwise, and the other program's version goes to a backup. A short message says what happened, with "See Diff" and, in the diff title bar, "Use Change from Disk" or "Replace My View", each leaving an "Undo" strip at the top of the tab. Waiting messages on background tabs are counted in a dedicated status bar item ("1 message for you") with "Go to Waiting Message" in the Command Palette. The setting `tandemMarkdown.outsideChanges.whenBothChanged` uses the other program's words there instead.
- A note with nothing unsaved takes another program's version of the file as it is, keeping a quiet backup of the previous text before replacing it. If the file on disk stays cut short after a retry, Tandem Markdown writes a part in the conflict file and marks the spot in the Problems list.
- A conflict file beside a note (the note's name with `.conflict` added) for each change that could not be settled, written for an AI agent to read and act on. The status bar counts what is unsettled, a warning in the Problems list marks each place, and "Copy Prompt for Agent" copies a sentence to give the agent. The first time a conflict file is written in a workspace, Tandem Markdown offers once to add instructions for agents; "Add Agent Instructions" adds them at any time, to `AGENTS.md` and in a rule file for Claude Code. The setting `tandemMarkdown.conflictFiles` turns conflict files off.
- Backups of every text set aside or replaced, kept for 30 days in the extension's own storage. "Compare with Backup" lists a note's backups beside its text, each with "Copy path", and a button on the note's tabs, shown while the note has a backup a message told of until "Done with these backups" in that list, opens the same list.
- Drawing: headings, emphasis, lists and task lists, quotes, code blocks with syntax colors, tables, front matter as a table, links, wikilinks, images, footnotes, highlights and rules, in the look of GitHub's markdown.
- Drawing what other programs write: math with dollars (prices stay text), `$$` and `math` blocks, which open to their source with the drawing kept beneath it; GitHub's alerts and Obsidian's callouts; tags, which search the workspace; emoji codes on GitHub's list; and the HTML GitHub keeps in a line, such as `<kbd>`, `<sub>`, `<br>` and `<img>`, cleaned through GitHub's allow-list. Each syntax beyond CommonMark and GitHub's has a setting under `tandemMarkdown.syntax`.
- Drawing the rest of HTML: blocks as a browser draws them (tables, figures, aligned pictures, a `<picture>` for each theme), wrappers with markdown inside (`<details>`, which folds on a click without changing the file, `<div align>`, `<center>`), HTML and pictures inside table cells, `<a href>` as a link and `<a name>` as a link target. Pictures from other programs: stored in the file, sized as Obsidian, Foam, Pandoc, Azure DevOps and Logseq write it, or shown for one theme. Video and sound players behind `tandemMarkdown.syntax.media`, off by default.
- Footnotes numbered as GitHub numbers them, each note's text on hover over its number, and a jump from a reference to its note and back with the keys a link opens with; footnotes written in place (`^[…]`).
- One tilde read as both GitHub and Pandoc write it: struck through by GitHub's rule (`A ~gone~ word`; `~5 to ~10` stays text), and subscript or superscript where a pair sits straight after a word with no space inside (`H~2~O`, `x^2^`). A setting chooses either reading alone.
- Obsidian's `%%comments%%`, faded in the Rich editor and hidden in Rich view; tasks with another mark in the box (`- [?]`) as boxes showing the mark; highlights in Obsidian's six colors (`==🔴Important==`); wikilinks in front matter values as links; and a setting to read wikilinks with the shown text first, as Dendron and GitLab wikis write them.
- Drawing what document tools and site builders write: `:::` boxes and `!!!` admonitions, attributes after a heading, Pandoc's styled spans and Word's bookmarks, TOML front matter, definition lists, grid tables (with interactive task checkboxes inside cells), abbreviations, code fence labels in braces or with words attached, and math in LaTeX's delimiters as chat assistants write it. Off unless switched on: JSON front matter, tracked-change marks, content tabs, `>>>` quotes and math with doubled backslashes.
- Mermaid diagrams, drawn in a sandboxed frame of their own and shown as pictures in the editor's theme; contents lists for `[TOC]`, `[toc]` and `[[_TOC_]]`, kept current; embedded notes (`![[Note]]`, a heading's section or a block), read-only and read again when the note changes; block ids faded or hidden, and a link to a block previews it.
- Editing: a toolbar (with a compact eye/pencil mode toggle and back-to-code pill pinned top-right on narrow panes) and shortcuts for formatting and blocks, list and quote continuation, tables edited in place, find and replace, paste from web pages, documents and spreadsheets, and `tandemMarkdown.lineHeight` alongside font size, font family, and content width.
- Heading section folding in both rich views (gutter chevrons, Toggle Section Fold, Fold All Sections, Unfold All Sections, and automatic unfolding on cursor navigation), plus drag-to-reorder sections in the Explorer outline.
- A menu on `/`, and the toolbar's Insert button, that inserts anything the editor draws: headings, lists, callouts, code, diagrams, math, tables, pictures, links, footnotes, a contents list, a definition list, front matter and the inline formats.
- A Mermaid diagram opened large over the editor, to zoom and move around.
- Git's conflict markers shown as one conflict, its sides labeled, with buttons to accept either side or both, and a way to VS Code's merge editor or to Source.
- A click in a table cell opens it with the cursor where the click was.
- Tab Moves Focus (`Ctrl+M`, `Ctrl+Shift+M` on a Mac): Tab and Shift+Tab move focus instead of indenting, in every rich tab, with a status bar item while it is on and a rich tab is active.
- On a Mac, tooltips and labels name Mac keys, and Option with a letter types its character in the find box.
- Each rich tab's text area is named for screen readers by its view and file, such as "Rich editor, notes.md".
- Renaming or moving an open file in VS Code: a rich tab comes back as a rich tab, in the same view, and unsaved edits are not mistaken for a change made by another program.
- Beside VS Code's own Markdown Editor or another extension's rich editor: a change another program makes to a file you are typing in there waits, and is merged when you pause, switch tabs, leave the window or save.
- A word count and the view's name in the status bar, and an outline of the file's headings in the Explorer.
- Each note reopens where it was left, in the same rich view, with its cursor and scroll position, also after VS Code restarts.
- A "Review in Source" button on a rich tab while Copilot has changes waiting in the note, which switches the tab to Source, where Copilot's review shows.
- "Copy Relative Path with Line Numbers", which puts the note's path and the selected lines (`notes/Field notes.md:12-18`) on the clipboard, to paste into an agent's chat.
- Problems that other extensions (spell checkers, linters) and VS Code's markdown link check report are underlined in both rich views, with their message on hover and their quick fixes from the pointer or `Ctrl+.` (`Cmd+.` on a Mac), applied by VS Code.
- Rename (`F2`) of a heading, a link or a reference, and suggestions for a link's or picture's address, through VS Code's markdown support.
- Git change marks in the Rich editor's margin for the lines changed since the last commit, with click-to-peek and one-click Revert, controlled by `tandemMarkdown.changeMarks`.
- `.txt` files and untitled files can be opened in the rich views; neither opens there by default.
- Commands: Verify File, Copy Diagnostics (redacted environment and log summary with no note text), Open Backup Folder, Show Keyboard Shortcuts, Go to Waiting Message, and Use Tandem Markdown by Default / Use Source by Default. With Tandem Markdown as the default editor, comparisons such as git's never open in a rich view: they stay in VS Code's own comparison view, or in the one the user chose.
- Window setting `tandemMarkdown.hideBuiltInPreviewButtons` (on by default) hides VS Code's redundant built-in Markdown preview title-bar icons while leaving its preview commands and shortcuts working.
- For markdown files, VS Code does not ask before saving over a file that is newer on disk, because the newer file has already been merged in. `WORKING_WITH_AGENTS.md` says how to bring the question back.
